# AI Assistant Bot

Telegram AI-ассистент с историей диалога, настройками ответа и понятными командами. Это самостоятельный демонстрационный MVP для портфолио: код готов к запуску со своими ключами, но публичный бот и доступ к платному API в репозитории не предоставляются.

## Возможности

- Отвечает на текстовые сообщения через OpenAI Responses API.
- Хранит пользователей, настройки и полную историю в SQLite через SQLAlchemy 2.x.
- Передаёт модели только 20 последних сообщений текущего пользователя.
- Поддерживает три стиля ответа: кратко, обычно и подробно.
- Показывает индикатор набора текста, пока выполняется запрос к модели.
- Разбивает длинный ответ на части, подходящие для Telegram.
- Различает таймаут, неверный ключ, лимит API, ошибку БД и ошибку Telegram; подробности остаются в логах.
- Не сохраняет неуспешный запрос в историю. Команда `/reset` удаляет историю, сохраняя выбранный стиль.

## Стек

Python 3.11+, aiogram 3, официальный Python SDK OpenAI, SQLAlchemy 2, aiosqlite, python-dotenv. Код асинхронный. Для демонстрации используется SQLite; с драйвером `asyncpg` и PostgreSQL URL можно заменить хранилище без переписывания бизнес-логики.

## Быстрый запуск

1. Создайте бота в Telegram через [@BotFather](https://t.me/BotFather): отправьте `/newbot`, задайте имя и username, сохраните выданный токен.
2. Создайте API-ключ в [панели OpenAI](https://platform.openai.com/api-keys). API оплачивается отдельно от ChatGPT; перед запуском проверьте доступ к выбранной модели и лимиты проекта.
3. Установите Python 3.11 или новее и создайте виртуальное окружение в корне репозитория:

   ```bash
   python -m venv .venv
   ```

4. Активируйте окружение: Windows PowerShell — `.venv\Scripts\Activate.ps1`; macOS/Linux — `source .venv/bin/activate`.
5. Установите зависимости:

   ```bash
   python -m pip install -r requirements.txt
   ```

6. Скопируйте `.env.example` в `.env` и замените значения токена и ключа. На Windows: `Copy-Item .env.example .env`; на macOS/Linux: `cp .env.example .env`.
7. Запустите бота:

   ```bash
   python -m app.main
   ```

8. Откройте своего бота в Telegram и отправьте `/start`.

`.env` не попадает в Git. Не публикуйте настоящий токен бота и API-ключ. База `bot.db` создаётся автоматически при первом запуске и также игнорируется Git.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather |
| `OPENAI_API_KEY` | Ключ проекта OpenAI API |
| `OPENAI_MODEL` | Модель, по умолчанию в примере `gpt-5-mini` |
| `DATABASE_URL` | Асинхронный SQLAlchemy URL, по умолчанию `sqlite+aiosqlite:///./bot.db` |

Лимиты заданы в `app/config.py`: `MAX_HISTORY_MESSAGES = 20`, `MAX_USER_MESSAGE_LENGTH = 4000`, `MAX_OUTPUT_TOKENS = 1600`. Вызов модели использует `store=False`: историю хранит приложение, а не Responses API.

## Команды

| Команда | Что делает |
| --- | --- |
| `/start` | Приветствие и первый шаг |
| `/help` | Список команд |
| `/reset` | Полностью очищает историю текущего пользователя |
| `/settings` | Показывает модель, стиль, размер истории, user ID; кнопки меняют стиль |
| `/stats` | Сообщения, ответы AI, дата первого использования и стиль |

Бот отвечает только в личном чате и принимает текст. Пустой текст и сообщения длиннее 4000 символов не отправляются в API.

### Пример сценария

1. Пользователь отправляет `/start`, затем спрашивает: «Как составить короткое коммерческое предложение?».
2. Бот отвечает. Пользователь уточняет детали; предыдущие сообщения помогают сохранить контекст.
3. Через `/settings` пользователь выбирает «Кратко» и получает более сжатые ответы.
4. `/stats` показывает число запросов и ответов. `/reset` начинает новый диалог без старой истории.

## Структура проекта

```text
app/
  main.py                  запуск и сборка компонентов
  config.py                переменные окружения и лимиты
  bot/handlers/            команды, сообщения, настройки, ошибки
  bot/keyboards/           inline-кнопки настроек
  services/llm.py          OpenAI Responses API и ошибки провайдера
  services/conversation.py  диалог, настройки, блокировки по пользователю
  database/models.py       таблицы
  database/session.py      async engine и сессии
  database/repository.py   запросы к БД
  utils/                   разбиение текста и логирование
tests/                     проверки без внешних API
.env.example               безопасный шаблон конфигурации
requirements.txt           совместимые версии библиотек
```

## Проверка без ключей

```bash
python -m unittest discover -s tests -v
python -m compileall -q app
```

Тесты используют SQLite в памяти и подменяют вызов LLM. Они проверяют разделение пользователей, ограничение контекста, статистику, сброс истории, стиль и длинные ответы. Настоящий ответ модели и обмен с Telegram проверяются после установки собственных ключей. Без ключей `python -m app.main` завершится с понятным сообщением о настройке.

## Как адаптировать под бизнес

Заменить системную инструкцию в `app/services/llm.py` на правила компании, добавить допустимые темы и сценарии передачи человеку, подключить FAQ или базу знаний, согласовать сроки хранения диалогов и уведомления менеджеру. Перед реальным запуском нужны контроль расходов API, резервное копирование БД и мониторинг ошибок. Для круглосуточной работы запустите один экземпляр polling-процесса на сервере; публикация исходников на GitHub сама по себе бота не запускает.
